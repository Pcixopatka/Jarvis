# Дані гри

Сталі дані гри (те, що не змінюється під час гри: сила нечисті, імена, тексти) поступово переїжджають
із коду в таблиці `data/*.json`. Так влаштовані сучасні онлайн-ігри: кожен запис має сталий id, усі
таблиці читає один завантажувач із перевіркою, а змінити нечисть — це правка одного запису, а не пошук
по коді. Згодом ті самі файли читатиме й сервер.

Зараз у таблицях лежить **база нечисті** (`data/mobs.json`), а поведінка нечисті в бою — у
**механіках** (`scripts/mechanics/`, по файлу на вид), на які записи посилаються. Далі підуть речі,
світ, класи й завдання.

## Як це влаштовано

- `data/mobs.json` — один запис на вид нечисті. Ключ запису — рядковий id (`"mavka"`, `"zmii"`).
  **Id сталі назавжди**: на них посилаються збереження гравців і майбутній сервер. Не перейменовуй їх.
- `scripts/core/game_db.gd` (у коді — `const GameDB := preload("res://scripts/core/game_db.gd")`) —
  єдиний вхід до таблиць. Він:
  - вантажить таблицю один раз, коли вона вперше потрібна;
  - зводить числа до типів схеми: JSON дає всі числа дробовими (`3` приходить як `3.0`), тож цілі поля
    (`num`, `stats.xp`, `boss.tier`) стають цілими, а колір — `Color`;
  - заморожує записи: їх можна лише читати, спроба змінити дає помилку. Записи не копіюються, тож
    читати їх у бою дешево;
  - якщо файлу нема або він зламаний, гучно пише помилку з шляхом (`push_error`);
  - `GameDB.problems()` повертає перелік усього, що не так (порожній — усе гаразд). Тести вимагають,
    щоб він був порожній.
- Решта коду не знає про JSON і бере дані через `GameDB`: `mob(id)`, `mob_ids()`, `has_mob(id)`,
  `mob_name(id)`, `mob_plural(id)`, `quest_item(id)`, `has_boss(id)`, `boss_name(id)`, `boss_tier(id)`,
  `is_phase2_boss(id)`, `hit_status(id)`, `mechanic(id, boss)`, `death_sound(id)`, `mob_wiki(id)`,
  `boss_wiki(id)`, `boss_ids()`, `mob_by_num(n)`, `boss_by_num(n)`.
- Невідомий id не ламає гри: `mob(id)` дає порожній запис, назви — порожній рядок (або запасне слово,
  якщо його передали другим аргументом), ступінь — 0, голос — загальний, а в бою така нечисть має
  типові числа.
- Файл до гри потрапляє через `include_filter="data/*"` в обох пресетах `export_presets.cfg`
  (Godot 4 і сам кладе `.json` до збірки, бо вважає його ресурсом, але фільтр робить це явним і не
  залежить від того, чи так буде в наступних версіях рушія).
- `tools/data_format.gd` приводить файли до єдиного вигляду (сталий порядок полів, таби, справжні
  українські літери) і друкує `problems()`:
  `godot --headless --path . -s res://tools/data_format.gd` (з `CHECK=1` лише перевіряє).

## Запис нечисті

Поля йдуть у файлі саме в такому порядку. Обов'язкові позначено зірочкою.

| Поле | Тип | Що це |
|---|---|---|
| `num`* | ціле | Сталий номер запису: 1001, 1002... |
| `name` | рядок | Ім'я в однині («Мавка»). Без нього нечисть не можна ставити в місця й завдання. |
| `plural` | рядок | Родовий множини для завдань: «Знищ 10 **мавок**». |
| `quest_item` | рядок | Трофей для завдання «Принеси». |
| `stats`* | запис | `hp`*, `speed`*, `damage`*, `radius`* — дробові; `xp`* — ціле; `scale` — зріст (типово 1). Числа 1-го рівня: рівень, бос, еліта й місце множать їх у коді. |
| `color`* | `[r, g, b]` | Колір нечисті, частки від 0 до 1 (не hex: так не губиться точність). |
| `attack`* | запис | `windup`* — замах перед ударом, с; `ranged` — стріляє; `keep_distance` — тримається на такій відстані; `shoot_cd` — с між пострілами; `as_boss` — що інакше, коли вид веде бій як бос або ватажок (`ranged`, `shoot_cd`). |
| `hit_status` | рядок | Стан, який може накласти удар: `bleed`, `burn`, `plague`, `chill`, `weak` (див. `Status.INFO`). |
| `mechanic` | рядок | Механіка звичайної форми: `"mob/<файл>"` у `scripts/mechanics/` (див. «Механіки»). Без поля — звичайна нечисть без особливостей. |
| `sounds` | запис | `death` — голос смерті (див. `SoundIndex.SFX`); без нього — загальний «enemy_die». |
| `wiki` | запис | `text`*, `tip`* — опис і порада для довідника. Вид має стояти й у `WikiData.ENEMY_ORDER`. |
| `boss` | запис | Є, якщо вид буває іменним босом: `num`* — сталий номер боса (2001, 2002...); `name`* — ім'я боса; `tier` — ступінь золотих речей 1–6 (без нього рахується за рівнем лігва); `phase2` — лютішає на половині здоров'я; `mechanic` — механіка боса, `"boss/<файл>"`; `wiki` — `text`*, `tip`* для довідника (і вид у `WikiData.BOSS_ORDER`). |

Поля «так/ні» пишуться лише тоді, коли вони «так». Невідоме поле — помилка (захист від описок).

Звичайна нечисть:

```json
"mavka": {
	"num": 1001,
	"name": "Мавка",
	"plural": "мавок",
	"quest_item": "Вінок мавки",
	"stats": {"hp": 30.0, "speed": 150.0, "damage": 8.0, "xp": 3, "radius": 16.0},
	"color": [0.6, 0.92, 0.65],
	"attack": {"windup": 0.3},
	"hit_status": "chill",
	"sounds": {"death": "die_spirit"},
	"wiki": {
		"text": "Лісова дівчина з вінком. Швидка й крихка, її удар студить.",
		"tip": "Холод уповільнює: не давай мавкам себе обступити."
	}
}
```

Нечисть, що буває й босом, має ще запис `boss` (див. `"upyr"` у файлі).

### Номери записів

- Кожна нечисть має свій `num` (1001...), кожен бос — свій `boss.num` (2001...). Номери не
  повторюються ні серед нечисті, ні серед босів.
- **Номер сталий назавжди.** Нова нечисть бере наступний вільний номер (найбільший у файлі плюс
  один), новий бос — так само серед босів. Номер вилученої нечисті більше нікому не віддають.
- Код гри й збереження посилаються на рядковий id; номер — для бази, сервера й людей.

## Як змінити силу нечисті

1. Знайди запис у `data/mobs.json` за id і зміни число в `stats` чи `attack`.
2. Перевір: `godot --headless --path . -s res://tools/data_format.gd` має сказати «Проблем у даних: 0».
3. Запусти тести. Деякі тести балансу можуть упасти, якщо зміна велика: це навмисно.

Масштаб за рівнем, множники боса, еліти й місць — це правила, вони в коді (`Enemy.setup`, `Data`).

## Механіки

Сила, ім'я й номер нечисті лежать у базі, а те, **як вона б'ється**, — код. Кожен вид, що вміє щось
своє, має власний файл у `scripts/mechanics/`, а запис у `mobs.json` лише називає його. Так сервери
онлайн-ігор прив'язують назву скрипту до запису істоти.

```
scripts/mechanics/
  mechanic.gd      основа: хуки й спільні цеглини
  boss/<вид>.gd    бос: усе обертання прийомів, лють, стрільба
  mob/<вид>.gd     звичайна форма: особливий прийом, ривок, власний постріл, крадіжка, хмара по смерті
  parts/           спільні частини кількох босів: feast.gd (бенкет), wind.gd (хуртовина), rocks.gd (каміння зі стелі)
```

- **Посилання** — шлях від `scripts/mechanics/` без `.gd`: `"mechanic": "mob/chort"` у записі,
  `"mechanic": "boss/koshchii"` у його `boss`. Звичайна форма бере файли лише з `mob/`, бос — лише з
  `boss/`. Ім'я файлу збігається з id виду.
- **Яку механіку бере нечисть.** Вид у бою як бос (і має запис `boss`) — механіку з `boss.mechanic`.
  Інакше — з `mechanic`. Ватажок хвилі, що б'ється як бос, але запису `boss` не має, тримає механіку
  звичайної форми (ривок, постріл, крадіжка діють), а прийом у нього типовий босів.
  Мари Відьми, Білої Пані й Велняса — звичайна форма свого виду: тому `mob/bila_pani.gd` і
  `mob/velnias.gd` мають лише їхній постріл.
- **Якщо боса й звичайну форму поєднує щось спільне** (вовкулака стрибає в обох формах, чаклун однаково
  стріляє), файл боса походить від файлу звичайної форми: `extends "res://scripts/mechanics/mob/vovkulaka.gd"`.
  Так само два схожі види: `mob/stallo.gd` походить від `mob/almasty.gd` і лише ширшає коло стрибка.
- **Вантаження.** Рушій (`Enemy.setup`) бере скрипт за посиланням раз на всю гру й створює на кожну
  нечисть свій об'єкт механіки (`e.mechanic`). Теки під час гри ніколи не переглядаються: у збірці
  для телефона скрипти лежать як `.gdc` з переадресуванням, і `load()` за шляхом до `.gd` іде за ним
  сам. Нечисть без механіки має `mechanic == null` і нічого за це не платить.
- **Перевірка** (`GameDB.problems()`, тести, `tools/data_format.gd`): кожне посилання веде на файл, що
  походить від `mechanic.gd`; тека відповідає формі; кожен файл у `mob/` і `boss/` потрібен
  якомусь запису (сиріт нема). `parts/` — лише предки, записи на них не посилаються.

### Хуки

Механіка пише лише ті хуки, які їй потрібні; хуків, яких вона (чи її предок) не написала, рушій не
кличе зовсім. `e` — сама нечисть (`Enemy`), `combat` — бій.

| Хук | Коли рушій його кличе |
|---|---|
| `setup()` | У `Enemy.setup`, коли числа виду, рівень і множники боса вже пораховано (типові таймери боса — ще ні). |
| `tick(delta)` | Щокадру, поки нечисть жива, ще до перевірки приголомшення: бенкет, хуртовина, погляд, каміння, власні таймери. |
| `chase(target, dist, dir, delta)` | Щокадру, коли нечисть не приголомшена й має ціль: ривки, телепорти. |
| `ability(target, dist)` | Спливло `e.ability_timer`. Бос: черговий крок обертання (`e.ability_step` уже збільшено). Звичайна нечисть: її прийом, лише не мара й не посеред замаху; перший — через 2–4,5 с. Хук сам ставить `e.ability_timer` до наступного разу. |
| `volley(dir)` | Спливло `e.shoot_timer` у того, хто стріляє (`attack.ranged`). Без хука — типовий постріл. |
| `phase2()` | Бос із `boss.phase2` упав нижче половини здоров'я. Спільне (швидкість, частіші постріли, рев) рушій уже зробив; тут гасло й підмога, зазвичай `rage("…", [види])`. |
| `on_hit(target)` | Удар нечисті поранив ціль. |
| `on_damage(amount)` | Нечисть отримує удар (amount — після множників, до зменшення здоров'я). |
| `on_lethal() -> bool` | Удар мав би вбити; `true` — не вмирає (Кощій встає знову). |
| `on_death()` | Нечисть загинула. |

Цеглини основи: `telegraph(форма, місце, секунди, шкода)` — попередження на землі (коло, конус,
смуга; `t.on_fire` спрацює, коли воно вдарить), `summon(види, скільки)`, `summon_free(...)` (без
досвіду), `shoot(...)`, `rage(гасло, види)`, `cast_illusions(ціль)`, `dir_to(ціль)`, `alive()`.
У діях, що спрацюють згодом (`t.on_fire = func(): ...`), перевіряй `alive()`, перш ніж рухати
нечисть: попередження скасовується, якщо нечисть загинула, але так певніше.

Числа прийомів (шкода, радіуси, перезарядки) — частина коду механіки, у таблицю вони не йдуть.

### Як додати нового боса

1. Запис у `data/mobs.json` (див. «Як додати нову нечисть») із записом `boss`: наступний вільний
   `boss.num`, ім'я, `tier`, за потреби `"phase2": true`, і `"mechanic": "boss/<вид>"`.
2. Файл `scripts/mechanics/boss/<вид>.gd`. Найменший:

   ```gdscript
   extends "res://scripts/mechanics/mechanic.gd"
   ## Лісовий цар: тупає довкола себе й кличе вовкулак.


   func ability(target, _dist: float) -> void:
   	e.ability_timer = 4.0 if e.phase2 else 5.0
   	match e.ability_step % 2:
   		1:
   			# Тупіт довкола себе
   			var t = telegraph("circle", e.global_position, 1.0, e.damage * 1.4)
   			t.radius = 200.0
   		0:
   			Audio.play("roar", 0.05, -4.0)
   			summon(["vovkulaka"], 2)


   func phase2() -> void:
   	rage("Лісовий цар лютує!", ["vovkulaka", "upyr"])
   ```

   Без `ability` бос б'є типово: коло там, де стоїть герой. Без `phase2` — гасло «Бос лютує!».
   Стріляє (`attack.as_boss.ranged`) — допиши `volley(dir)`, інакше постріл типовий.
3. `godot --headless --path . --import` (Godot дасть новому скрипту `.uid`, його теж кладуть у git),
   тоді `tools/data_format.gd` і тести: вони скажуть, якщо посилання хибне чи файл нікому не потрібен.
4. Решта — як для будь-якого боса: лігво в `Data.LOCATIONS`, `WikiData.BOSS_ORDER`, вигляд.

### Як дати звичайній нечисті прийом

1. Файл `scripts/mechanics/mob/<вид>.gd` із хуком `ability` (і, якщо треба, `chase`, `volley`,
   `on_hit`, `on_death`):

   ```gdscript
   extends "res://scripts/mechanics/mechanic.gd"
   ## Болотяник: плюється багнюкою під ноги героя, і та уповільнює.


   func ability(target, dist: float) -> void:
   	e.ability_timer = randf_range(5.0, 7.0)
   	if dist > 500.0:
   		e.ability_timer = 1.0  # задалеко: спробує трохи згодом
   		return
   	var pos: Vector2 = target.global_position
   	var t = telegraph("circle", pos, 1.0, e.damage * 0.8)
   	t.radius = 80.0
   	t.on_fire = func(): combat.spawn_plague(pos, e.damage * 0.25, "chill", Color(0.4, 0.5, 0.3), 3.0)
   	e.cast_time = 0.6
   ```

2. У записі виду: `"mechanic": "mob/<вид>"`.
3. `--import`, `tools/data_format.gd`, тести.

## Як додати нову нечисть

1. Додай запис у `data/mobs.json`: новий id (малі латинські літери й «_»), наступний вільний `num`,
   ім'я, множина, трофей, `stats`, `color`, `attack`, за бажанням `hit_status`, `sounds`, `wiki`.
   Для боса — запис `boss` з наступним вільним `boss.num`.
2. Запусти `tools/data_format.gd`: він вирівняє запис і скаже, чого бракує.
3. Пропиши вид там, де він живе: `enemies` чи `boss` місця в `Data.LOCATIONS`, а також у порядку
   довідника (`WikiData.ENEMY_ORDER` / `BOSS_ORDER`), душі (`Souls`), розшук (`Activities.BOUNTY_NAMES`),
   за потреби артефакт і золоті речі. Ці таблиці поки в коді; `GameDB.problems()` перевіряє, що всі
   вони посилаються на нечисть, яка є в базі.
4. **Що потребує коду:**
   - вигляд: лист спрайтів (`tools/pixel/sprites.py`) або малювання `_draw_<вид>` в `enemy.gd`;
   - поведінка в бою — файл механіки (див. «Механіки»): прийом, обертання боса, лють, власна стрільба.
   Без механіки нова нечисть просто б'є зблизька (чи стріляє, якщо `ranged`) і малюється кружком.

## Що далі

- Механіки суперників у герці (`Enemy._rival_ability`) поки в `enemy.gd`: їхні прийоми залежать від
  стилю бою, а не від виду.
- Далі в таблиці переїдуть речі, світ (місця), класи й завдання — тим самим шляхом: файл у `data/`,
  схема й правила в `GameDB.TABLES`, той самий `problems()`.
